# Fleet Analytics Platform — Кейс для портфолио

> Проект от Jack: аналитическая платформа для автопарка, объединяющая данные из Битрикс24, UIS и 1С.

## Проблема

Компания работает с автопарком: продажи ведут в **Битрикс24**, звонки идут через **UIS**, а учёт машин, водителей и заказов живёт в **1С**. В итоге никто не видит единой картины:

- непонятно, сколько звонков превращается в сделки и выдачи;
- не видно, какой автомобиль приносит деньги, а какой сидит в простое;
- непонятно, на каком этапе воронки теряются клиенты;
- менеджеры спорят о цифрах, потому что каждый считает в своей системе.

## Что я сделал

Построил аналитическую платформу, которая забирает данные из трёх источников, складывает их в единое хранилище, рассчитывает проверяемые показатели и показывает их в дашборде Metabase.

## Стек

- **FastAPI + SQLAlchemy asyncpg** — ingestion, API, витрины.
- **PostgreSQL 16** — хранилище данных.
- **Redis 7** — брокер для Celery.
- **Metabase** — BI-дашборды.
- **Docker Compose** — локальный запуск всего стека.
- **Alembic** — миграции схемы БД.
- **Celery Beat** — ежедневная синхронизация и пересчёт витрин.

## Что реализовано

### 1. Интеграции

- Webhook-эндпоинты для **Битрикс24**, **UIS** и **1С** с авторизацией по токену.
- Mock-эндпоинты, повторяющие структуру реальных API, чтобы можно было разрабатывать без доступа к боевым системам.
- Все входящие события сохраняются в `raw_events` для аудита и повторной обработки.
- Фоновая синхронизация через Celery Beat.

### 2. Единая модель данных

- `crm_contacts`, `crm_deals` — CRM.
- `calls` — телефония.
- `vehicles`, `drivers`, `transport_orders`, `repairs`, `fuel_transactions` — парк и операции.
- Связь между системами по телефону, `deal_id`, `vehicle_id`.

### 3. Аналитические витрины

- `mart_call_conversion` — конверсия звонков в сделки по месяцам.
- `mart_vehicle_efficiency` — выручка, затраты, прибыль по автомобилям.
- `mart_order_profitability` — прибыльность каждого заказа.
- `mart_vehicle_downtime` — дни простоя и затраты на ремонты.
- `mart_vehicle_fuel_efficiency` — расход топлива.
- `mart_customer_ltv` — пожизненная ценность клиента.

Витрины пересчитываются одной командой `POST /analytics/recalc`.

### 4. Дашборд Metabase

21 визуализация в едином дашборде.

**Воронка продаж:**

- Воронка: заявка → звонок → выдача.
- Конверсия по этапам воронки (% от заявок).
- Конверсия звонков по месяцам.

**Качество обработки звонков:**

- Пропущенные звонки по месяцам.
- Средняя длительность звонка по операторам.
- Распределение длительности звонков.

**Заказы и выручка:**

- Заказы по статусам.
- Тренд количества заказов по месяцам.
- Выручка по месяцам.
- Прибыльность заказов (таблица).
- Топ 10 убыточных заказов.
- Распределение прибыли заказов.

**Парк:**

- Прибыльность автомобилей.
- Доходность по моделям.
- Средняя прибыль на заказ по моделям.
- Загрузка автопарка по статусам.
- Простой автомобилей (дни).
- Средний расход топлива по моделям.
- Количество заправок по автомобилям.
- Суммарные затраты на ремонт по моделям.

**Клиенты:**

- Топ клиентов по LTV.

### 5. Проверка качества данных

Эндпоинт `GET /data-quality/` возвращает сводку: общий статус и 13 проверок. Например:

- дубли контактов по телефону;
- звонки без привязки к сделке/контакту;
- заказы без ТС или водителя;
- отрицательная выручка/затраты;
- аномальный расход топлива;
- выигранные сделки без выданного автомобиля;
- ремонты с отрицательной длительностью.

### 6. Пояснение расчётов

Все формулы открыты через API:

```bash
curl http://localhost:8000/analytics/calculations
```

Ключевые показатели:

- **Конверсия звонков** = `calls_with_deal / calls * 100` (сделка связана, если `deal_id is not null`).
- **Прибыль автомобиля** = `sum(revenue) - sum(cost)` по всем заказам ТС.
- **Прибыль заказа** = `revenue - cost`.
- **Маржа заказа** = `profit / revenue * 100`.
- **Простой** = `sum(ended_at - started_at)` по ремонтам.
- **Расход топлива** = `liters / distance_km * 100`.
- **LTV клиента** = `sum(revenue) - sum(cost)` по всем заказам клиента.

## Результат

- Показатели считаются из одного источника правды.
- Можно проверить любую цифру до исходной записи.
- Дашборд доступен по публичной ссылке для демонстрации.
- Все endpoint покрыты тестами: 21 тест, все проходят.
- 21 визуализация в дашборде.
- Формулы всех показателей открыты через API `/analytics/calculations`.
- Ежедневная синхронизация и пересчёт витрин через Celery Beat.

## Как запустить

```bash
cd ~/projects/fleet-analytics
docker compose up -d --build
cd app
docker compose exec app alembic upgrade head
docker compose exec app python scripts/setup_metabase.py
```

- API: http://localhost:8000/docs
- Metabase: http://localhost:3000
- Тесты: `docker compose exec app python -m pytest tests/test_api.py -v`
