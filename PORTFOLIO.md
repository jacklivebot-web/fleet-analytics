# Fleet Analytics Platform — Кейс для портфолио

## Проблема

Компания арендует ~1 400 автомобилей в восьми городах. Данные о продажах, звонках и парке живут в разных системах: Битрикс24, UIS, 1С. Руководители принимают решения без единой картины: непонятна конверсия заявки в выдачу, не видно доходность конкретного автомобиля, теряются клиенты на этапах воронки.

## Решение

Построил аналитическую платформу, которая собирает данные из трёх источников, рассчитывает проверяемые показатели и показывает их в едином дашборде.

## Стек

- **FastAPI + SQLAlchemy asyncpg** — ingestion, API, витрины
- **PostgreSQL 16** — хранилище
- **Redis 7** — кеш / очередь (заготовка)
- **Metabase** — BI-дашборды
- **Docker Compose** — локальный запуск
- **Alembic** — миграции базы данных

## Что реализовано

### 1. Интеграции
- Webhook-эндпоинты для Битрикс24, UIS, 1С с авторизацией по токену.
- Mock-эндпоинты, повторяющие структуру реальных API.
- Все входящие события сохраняются в `raw_events` для аудита.

### 2. Единая модель данных
- `crm_contacts`, `crm_deals` — CRM.
- `calls` — телефония.
- `vehicles`, `drivers`, `transport_orders`, `repairs`, `fuel_transactions` — парк.
- Связь: телефон, `deal_id`, `vehicle_id`.

### 3. Аналитические витрины
- `mart_call_conversion` — конверсия звонков в сделки по месяцам.
- `mart_vehicle_efficiency` — выручка, затраты, прибыль по автомобилям.
- `mart_order_profitability` — прибыльность каждого заказа.

### 4. Дашборд Metabase

16 визуализаций в едином дашборде:

**Воронка продаж:**
- Воронка: заявка → звонок → выдача.
- Конверсия по этапам воронки (% от заявок).
- Конверсия звонков по месяцам.

**Качество обработки звонков:**
- Пропущенные звонки по месяцам.
- Средняя длительность звонка по операторам.
- Распределение длительности звонков.

**Заказы и выручка:**
- Заказы по статусам.
- Тренд количества заказов по месяцам.
- Выручка по месяцам.
- Прибыльность заказов (таблица).
- Топ 10 убыточных заказов.
- Распределение прибыли заказов.

**Парк:**
- Прибыльность автомобилей.
- Доходность по моделям.
- Средняя прибыль на заказ по моделям.
- Загрузка автопарка по статусам.

### 5. Пояснение расчётов

Все формулы открыты через API:

```bash
curl http://localhost:8000/analytics/calculations
```

- **Конверсия звонков:** `calls_with_deal / calls * 100`. Сделка считается связанной, если `deal_id` не null.
- **Прибыль автомобиля:** `sum(revenue) - sum(cost)` по всем заказам ТС.
- **Прибыль заказа:** `revenue - cost`.
- **Маржа заказа:** `profit / revenue * 100`.

## Результат

- Показатели считаются из одного источника правды.
- Можно проверить любую цифру до исходной записи.
- Дашборд доступен по публичной ссылке для демонстрации.
- Все endpoint покрыты тестами: 16 тестов, все проходят.
- 16 визуализаций в дашборде.
- Формулы всех показателей открыты через API `/analytics/calculations`.

## Как запустить

```bash
cd ~/projects/fleet-analytics
docker compose up -d --build
cd app
docker compose exec app alembic upgrade head
docker compose exec app python scripts/setup_metabase.py
```

- API: http://localhost:8000/docs
- Dashboard: http://localhost:3000/public/dashboard/8403a20a-d24e-45f0-85b8-b5aef11ecd30
- Тесты: `docker compose exec app python -m pytest tests/test_api.py -v`
